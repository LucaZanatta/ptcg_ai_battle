    c023: the veto primitive, conservative admission, and the expert shortlist
    
    Three mechanisms, each answering a measured failure of the previous one.
    
    The veto primitive: a rule that says 'not that one' needs a replacement, and the only
    principled replacement is the expert's own next preference. The observation is copied with
    the vetoed options removed and the SIMULATION instance of the base agent is asked to choose
    from what remains -- so the real instance is still called exactly once per real decision and
    its plan state advances exactly once.
    
    Conservative admission (prize_only): the planner overrides only on a lexicographic gain in
    (terminal, prizes taken, prizes conceded) -- facts about the simulated line rather than
    opinions about board quality. With use_ko_risk it also compares the prizes the opponent can
    immediately take back, computed from their visible active, its attached energy and its
    public attacks.
    
    The expert shortlist: plan_screen1 lost monotonically in override rate, so the search is now
    restricted to the expert's own top-k, obtained by re-asking it with each previous choice
    vetoed. Every candidate is expert-approved and the search only breaks the tie.
    
    Also: determinization now rotates which unseen cards land in the prizes -- without it the
    same cards were hidden in every prize slot of every game, a systematic bias rather than a
    sample.

    c023: infrastructure -- player registry, fork-per-game evaluation harness, candidate builder
    
    The harness forks one child per game rather than reusing pool workers. Several public
    agents call the engine's search API without releasing every handle, and the engine's
    handle buffer has capacity 7: the eighth allocation throws an uncaught C++ exception,
    the worker dies by SIGABRT, and multiprocessing.Pool waits forever for a result that
    will never arrive. The first run of this harness hung with every worker at 0% CPU for
    exactly that reason.
    
    Two integrity probes ride along: identity fields travel with every job (never re-attached
    by position), and each decision is compared against the mindless legal fallback, so an
    agent whose module failed to load reads as broken rather than as weak. That probe caught
    a real bug here -- restoring sys.path after import made tetsutani's lazily-imported
    policy unavailable, and it played the fallback for a whole game while scoring 1/6.
